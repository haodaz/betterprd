# 文档体检台

**不以 AI 验 AI　·　拒绝幻觉膨胀　·　拒绝废话文档**

👉 **[www.betterprd.com](https://www.betterprd.com/)**　打开就能用，不用注册、不用装任何东西。

把一份 PRD / 方案 / 报告粘进去，输出**开工前必须让活人回答的问题**。

打开 `prd-check.html` 就能用。没有构建步骤，没有依赖，不需要装任何东西。

## 两个模式，措辞完全不一样

**自检（默认）** —— 这是你自己写的文档，发出去之前先过一遍。
它不挑错，只告诉你：哪几处会让接手的人卡住、卡住之后业务上会怎样、**你发出去之前最好先补上什么**。
导出的是一份自查清单。

**体检** —— 这是别人给你的文档，你要判断能不能照着干。
每条给出问题点、业务影响、以及该找哪个活人确认什么。导出的是一条可以直接发群的消息。

默认是自检，这是有意的。一个只能用来挑别人毛病的工具，第一次用完就会被所有人记恨。
你得能说「我自己每份文档发出去之前都过一遍」，别人用它才不觉得被针对。

## 它不做什么：AIGC 检测

市面上的检测只回答一个问题：「这是不是 AI 写的？」

在真实工作里这个问题没有意义——答案永远是「是」，而且本来就该是。现在没人全手写文档，也不必。

真正要查的是另外三件事，缺一不可：

**问题点 → 不处理会怎样 → 该找哪个活人确认什么**

只说「这里有问题」而不说「不处理会怎样」和「去找谁」，等于没说。

## 它查什么

一份文档最危险的地方，不是写错了，而是**把未决问题排版成了已决问题**——

参数表左边给出精确的默认值，右边小字写着「需业务确认」；数据源清单里第一环标着「待定」，后面十一章的公式照样算得好好的。读的人只会记住左边、只会看到公式，于是整条链路在一个不存在的输入上开工。

目前的检测项：

| 规则 | 找的是什么 |
|---|---|
| 未决伪装 | 精确默认值旁边自己标着「需确认 / 待定 / TBD」 |
| 悬空依赖 | 输入还没拿到，下游公式和图表已经写完了 |
| 缺失却照算 | 一边标「数据缺失」，一边照样给出了结果 |
| 补丁痕迹 | 「修正说明 / 原文应为」——上一版是整体生成、没人逐句核过 |
| 未验证具体物 | 包名、CLI、接口地址、带路径的 URL，幻觉率最高的部分 |
| 无源数字 | 阈值、权重、系数，前后找不到任何出处 |
| 空心自动化 | 「系统自动 / AI 智能地」做某事，没写触发条件和输入输出 |
| 空心词 | 删掉之后句子信息量不变的那些词 |
| 无验收 | 全文没说「怎么判断做对了」 |
| 无源比例 | 百分比结论没写口径——分母是什么、怎么统计的 |
| 条件化承诺 | 一边写「100% 自动」，一边承认前提还没达成 |
| 权重不配平 | 声明为权重的百分比加起来不等于 100% |
| 数量对不上 | 写着「5 项：」后面却列了 6 个 |
| 口径冲突 | 同名参数不同值、同一个符号被定义成两个量、同一指标一处按月一处按季度 |
| 无依据的工期 | 「压缩至 20-30 秒」「6 个月为合理周期」，没写怎么估的 |
| 吹捧残留 | 「极其精妙」「极度炫酷」——模型对着作者说的话，被原样留在文档里 |
| AI 痕迹 | 章节模板复用 + 行文特征 + 文档自己声明了是 AI 生成的 |

## 关于 AI 痕迹标记

标出来不是为了抓人，是为了两件事：

- **给读的人一个心理准备**：哪几段可能没经过人工核对，看的时候多留个心眼
- **给写的人一个台阶**：「这段是我的 AI 自己加的，删掉就行」比「我写错了」容易说出口一百倍

指出问题如果等于指控对方能力有问题，对方只能硬撑，事情就谈不下去。把锅留给模型，沟通才能发生。

所以 AI 痕迹**单独一档，不计入「必须回答的问题」计数**，它的提问也是软的。

## 输出的是问题，不是评分

永远不给文档打分。分数会被辩论（「你凭什么说我 60 分」），问题不能被辩论——对方只能回答，或者回答不上来。回答不上来的那几条，就是这份文档真实的进度。

措辞一律是「这里需要一个人回答」，不是「这里错了」。

结果可以复制成一条能直接发群的消息，也可以下载 `.md` 报告和 `.json` 结果。

## English

The whole site is bilingual — it follows your browser language and remembers your choice.
Rule names, card copy, exports and the landing page all switch; detection vocabulary covers
both Chinese and English documents (`TBD`, `leverage`, `seamless`, `acceptance criteria`,
`it's important to note`, and so on), so an English PRD gets the same treatment.

## 一套文档一起查

一套材料里最危险的问题不在任何一份文档里面。真实例子：同一套评价体系，
A 文档写「C 维度 20%、D 维度 20%」，B 文档写「C 维度 15%、D 维度 25%」——
两份各自加起来都是 100%，各自都挑不出毛病，只有并排放才看得见。

`cross-check.html` 把一整套文档一起拖进去，列出所有「同一个名目、不同数字」的地方，
标明各自出自哪份的第几行。只比数字，不比意思，不判断谁对谁错。

## 它查不了什么

- **查不了内容对错。**它不懂你的业务，公式合不合理、指标有没有意义，一概不知，也不装懂。
- **口径冲突只查得到数值层面的。**同名参数不同值、符号复用、权重不配平、单位粒度不一致、窗口长度不一致，这五类查得到。用文字描述出来的定义分歧（两章对同一概念说法不同、都没给数）查不到，仍是缺口。
- **查不出「写得对但做不到」。**资源、排期、人力、授权，文档里不写就看不见。
- **命中不等于有罪。**每条只是「这里需要一个人回答」。答得上来就划掉。
- **它自己只是一堆正则。**没有模型参与，所以不会幻觉，但也绝不聪明。

写明边界是这个工具存在的理由本身。一份不肯说自己做不到什么的文档，正是它要查的东西。

## 你的文档不会离开你的电脑

没有后端、没有账号、没有上传、不联网、不调用任何模型。全部计算在你的浏览器里完成。

不用信这段话——代码就一个 HTML 文件，自己搜 `fetch`、`XMLHttpRequest`、`navigator.sendBeacon`，一个都没有。断网打开也照样能用。

## 改规则

规则在 `prd-check.html` 的 `/*RULES_START*/ … /*RULES_END*/` 之间，是不碰 DOM 的纯函数 `analyzeDoc(text)`，可以在 node 里直接拿真实文档回归测试：

```js
const fs = require("fs");
const html = fs.readFileSync("prd-check.html", "utf8");
const src = html.split("/*RULES_START*/")[1].split("/*RULES_END*/")[0];
const analyzeDoc = new Function(src + "; return analyzeDoc;")();
console.log(analyzeDoc(fs.readFileSync("你的文档.md", "utf8")));
```

改完规则请拿一份**真实的长文档**跑一遍再说做好了，别只看内置示例。
